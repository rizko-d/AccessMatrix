AccessMatrix

API Authorization Testing CLI

Verify who can access what. Define identities, requests and permission expectations; collect assertion evidence without exporting credentials or raw response bodies.

Source & quick startRoadmapCI

Explicit policies. Conservative verdicts.

  • Supplied test identities, environment credentials and anonymous checks.
  • Identity verification and positive controls before authorization assertions.
  • Read-only GET/HEAD tests; terminal and JSON reports.
  • PASS, FAIL, INCONCLUSIVE and ERROR remain distinct.
  • Loopback demo in vulnerable and fixed modes; no external Go dependencies.

Build locally

git clone https://github.com/rizko-d/AccessMatrix.git
cd AccessMatrix
go build -trimpath -o bin/accessmatrix ./cmd/accessmatrix
./bin/accessmatrix validate -config examples/demo.json
./bin/accessmatrix demo -vulnerable

Use the repository quick start for the second terminal, synthetic credentials and matrix execution.

What it does not claim

A passing suite means the configured checks passed. It does not prove the API has no authorization vulnerabilities. AccessMatrix does not discover permissions, brute-force identifiers or assign severity from status codes.
